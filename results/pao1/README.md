# Results of the PAO1 run

This directory holds the outputs of HRIBO 1.8.1 on the subsampled PAO1
libraries that are small enough to keep under version control, together
with every log of the run. manifest.tsv lists every file HRIBO produced,
with size and md5 sum, and says which ones were copied here. Files that were
not copied (alignments, coverage tracks) are regenerated by the scripts in
the repository root.

Read the files in this order.

## 1. Did the reads survive processing

- summary/read_processing.tsv. One row per library: reads in the SRA
  archive, reads kept by the subsampling, cutadapt's counts (reads with
  adapter, too short, written), and the read counts FastQC reported at each
  stage (raw, trimmed, rRNA-filtered, unique mappers).
- qc/multi/multiqc_report.html. The MultiQC report over all four stages.
  Open it in a browser. The read counts should fall step by step, not
  collapse at one stage.
- qc/multi/multiqc_data/*.txt. The tables behind the report.

For a Ribo-seq library the fraction of reads carrying adapter should be
above 90 percent, because 25 to 34 nt footprints are always shorter than
the 50 nt read. A low value here means the wrong adapter sequence.

## 2. Is this really Ribo-seq

- metageneprofiling/read_length_fractions.html and the SVG copies. The
  RIBO library should show a sharp peak in the footprint range; the RNA
  library should not.
- metageneprofiling/RIBO-GLY-1/. Metagene profiles around start and stop
  codons for each read length, 5' and 3' end mapping, three normalisations.

## 3. The summary tables

- auxiliary/overview.xlsx, also as .tsv and .gff. The merged table:
  annotated features and predicted ORFs with read counts.
- auxiliary/predictions_reparation.xlsx and auxiliary/predictions_deepribo.xlsx.
  ORFs called by each tool, with scores.
- auxiliary/annotation_total.xlsx and annotation_unique.xlsx. Read counts
  per annotated feature, all mappers and unique mappers. Use the unique
  counts for anything quantitative.
- auxiliary/total_read_counts.xlsx and unique_read_counts.xlsx. Library
  level totals.
- summary/orf_predictions.tsv. How many ORFs each caller reported at each
  stage, raw output and after HRIBO's filtering.

## 4. ORF caller output

- reparation/GLY-1/. Predicted_ORFs.txt is the raw table. The PDF and PNG
  files are Reparation's diagnostics: the metagene profile it built, the
  P-site offset it chose per read length, the S curve of its classifier
  and the precision-recall and ROC curves of its model.
- deepribo/GLY-1/. predictions.csv scores every candidate ORF in the
  genome; parameters.txt holds the coverage cut-offs HRIBO estimated for
  the library.
- tracks/. GFF files for a genome browser: the ORF calls of each tool
  after HRIBO's filtering (reparation_annotated.gff, deepribo_merged.gff)
  and the merged sets (GLY.merged.gff, all.gff). HRIBO also writes tracks
  of every candidate start codon, stop codon, alternative start codon and
  ribosome binding site in the genome; they are derived from the genome
  sequence alone, weigh over 40 MB together, and are listed in
  manifest.tsv but not copied.

## 5. Figures

Four PNG files drawn by scripts/10_plot_figures.py from the tables in this
directory, so they can be redrawn from the repository alone:

- figures/read_processing.png. Reads per library at each processing stage.
- figures/read_length_distribution.png. Footprint length distribution of
  the Ribo-seq library, with the 25 to 34 nt metagene window marked.
- figures/metagene_profile.png. 5' ends of 25 to 34 nt footprints around
  the start codon and 3' ends around the stop codon, counts per million,
  summed over the genes HRIBO kept.
- figures/orf_predictions.png. Length, start codon, annotation status and
  agreement of the Reparation and DeepRibo calls. The numbers are in
  summary/orf_agreement.tsv and summary/read_length_window.tsv.

HRIBO's own figure, figures/heatmap_SpearmanCorr_readCounts.pdf, is the
Spearman correlation of read counts between the two libraries. With one
RIBO and one RNA library it shows that the two are different, and nothing
more. pca/ is absent: the PCA step needs at least four samples, see
docs/troubleshooting.md in the repository root.

## 6. Counts

- readcounts/. The matrices everything downstream was computed from:
  mapped reads per library, mean read lengths, featureCounts output for all
  and unique mappers, counts over predicted ORFs.

## 7. Logs and provenance

- logs/snakemake_*.log. The complete output of every Snakemake invocation
  (dry run, environment creation, the run), including the cutadapt reports
  and every shell command executed.
- logs/snakemake/. Snakemake's own log files.
- logs/*_segemehl.log, logs/*_reparation.log. Per-rule logs written by HRIBO.
- logs/read_download_stats.tsv. Reads in each archive, reads kept, seed,
  fraction, md5 of each FASTQ file.
- logs/reference_provenance.tsv. Assembly, source URL, checksums, genome
  length.
- logs/*.vdb-validate.log. Integrity check of each SRA archive.
- logs/disk_usage.tsv. Size of the analysis directory and its parts at the
  end of the run.
- config_used/. The configuration and sample sheet exactly as HRIBO read
  them, plus the HRIBO version.
- summary/job_timings.tsv and summary/run_overview.tsv. Wall-clock time
  per rule and for the whole run, jobs finished, rules that failed.

## What these results are for

They document a complete, working run of HRIBO and show what each stage
produces on real data. They were computed on 10 percent of the reads. The
quality metrics of the libraries are trustworthy; the ORF calls and the
counts are not a substitute for the full-depth analysis and should not be
used for biological claims. See docs/methods.md in the repository root.
